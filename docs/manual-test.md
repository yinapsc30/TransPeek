# 手动验收清单

截取、面板窗口、全屏、多桌面这些行为依赖真实的窗口环境，无法用单元测试覆盖，发布前按本清单逐项检查（design.md「手动验收清单」）。括号中为对应的需求编号。

准备：从 Xcode 运行 TransPeek，授予屏幕录制权限并重启；准备一个能持续刷新文字的窗口（游戏聊天频道，或在“终端”中运行 `while true; do date; sleep 1; done`）。

## 权限与菜单栏

- [ ] 未授权时启动，显示权限引导窗口；菜单栏菜单显示“未授予屏幕录制权限”，截取相关菜单项不可用（R1.1、R1.3）
- [ ] 授权并点击“重启 TransPeek”后可以正常使用（R1.2）
- [ ] 应用不出现在 Dock 中（R2.1）
- [ ] 四个快捷键在目标应用处于前台（包括全屏）时都能生效（R2.3）
- [ ] 其他应用占用快捷键时，菜单中显示冲突提示（R2.4）

## 窗口与截取

- [ ] “选择目标窗口”列出当前窗口，有图标、标题和缩略图，不包含 TransPeek 自己（R3.1）
- [ ] 未选择目标时，在目标应用前台按 ⌃⌥T 直接框选该应用的窗口（R3.2）
- [ ] 重新选择同一个应用时，自动恢复上次的区域和面板（R3.3、R4.7）
- [ ] 拖动、缩放目标窗口，面板在 300ms 内跟随（R3.4）
- [ ] 目标窗口被其他窗口遮挡时，面板仍持续更新（R3.7；部分游戏被完全遮挡后会停止渲染，记录实际表现）
- [ ] 最小化目标窗口，面板隐藏、识别暂停；恢复后自动继续（R3.5）
- [ ] 关闭目标窗口，面板保留历史并显示“窗口已关闭”（R3.6）
- [ ] 面板覆盖在区域上方时，译文不会被再次识别（R5.1）

## 区域

- [ ] 框选遮罩只允许在目标窗口内绘制，Esc 取消（R4.1）
- [ ] 框选后弹出配置，默认值为聊天、自动检测、系统语言、全局默认翻译配置（R4.2）
- [ ] 三种模式行为正确：单次（⌃⌥R）、对话（替换）、聊天（追加）（R4.3）
- [ ] 窗口缩放后区域按比例跟随（R4.4）
- [ ] 区域管理中可以重命名、改模式、改语言、改翻译配置、加忽略规则、暂停、删除、重新框选（R4.5、R4.6、R4.8）

## 识别与翻译

- [ ] 画面不变时 CPU 占用很低（活动监视器中单核 5% 以内）（R5.3、R14.2）
- [ ] 聊天滚动时新消息只出现一次，不重复；向上翻看原窗口历史不会产生新条目（R7.1、R7.3）
- [ ] 刷屏过快时出现“可能有遗漏”标记（R7.4）
- [ ] 未配置 API Key 时只显示原文，并提示去设置（R8.3）
- [ ] 目标语言为中文时，中文行直接显示原文，不消耗翻译调用；日文行仍然翻译（R8.9）
- [ ] 新版本首次启动约半分钟内框选区域，面板显示“正在加载文字识别模型”，加载完成后正常识别；之后启动时第一次识别不再等待（R14.5）
- [ ] 断网时条目显示失败标记，恢复网络后点击“重试”成功（R8.6）
- [ ] LLM 配置“测试连接”显示译文和耗时；模型 ID 填错时提示检查模型 ID（R16.11）
- [ ] LLM 失败且开启回退时，条目显示“已回退”（R16.12）
- [ ] Ollama 本地模型可用（不填 Key，http://localhost）（R16.1、R16.3）

## 面板

- [ ] 贴边面板长度与窗口边一致，外侧有空间时放在外侧（R9.1、R9.2）
- [ ] 窗口右侧只剩 200–320pt 时，面板缩窄后仍放在外侧；窗口贴着屏幕右边缘时，面板换到左侧外侧（R9.2）
- [ ] 游戏或其他应用在前台时，面板边缘仍可拖动调整大小，悬停时光标变化（R10.1）
- [ ] 窗口贴近屏幕边缘或全屏时，面板放在内侧、半透明，可以折叠成细边，悬停展开、离开 1 秒后折叠（R9.3）
- [ ] 拖动厚度手柄可以调整贴边面板的宽或高（R9.1）
- [ ] 悬浮面板可以拖动、拖动右下角调整大小，跟随窗口移动（R10.1、R10.2）
- [ ] 拖到窗口边缘附近显示蓝色吸附预览，松开后贴边；从边缘拖开变为悬浮（R10.3、R10.4）
- [ ] 透明度、字号、显示原文开关生效（R10.5、R11.1、R11.4）
- [ ] 悬浮面板高度小于 80pt 时只显示最新一条（R10.6）
- [ ] 在底部时自动滚动；向上滚动后有新消息时显示“↓ N 条新消息”，点击回到底部（R11.2、R11.3）
- [ ] 右键菜单：复制译文、复制原文、复制全部、清空历史（R11.4）
- [ ] 锁定后鼠标穿透到游戏，标题栏变暗；只能用快捷键或菜单解锁（R11.5）
- [ ] 点击面板按钮、面板更新时，游戏不会失去前台和键盘焦点（R11.6）
- [ ] 关闭面板后区域变为暂停，在区域管理中恢复后面板重新出现（R11.7，多栏面板见下方“合并面板”）

## 全屏与多桌面

- [ ] 目标应用进入 macOS 原生全屏后，面板显示在全屏桌面中（R12.1）
- [ ] 切换到不包含目标窗口的桌面时，面板隐藏（R12.3）

## 性能（R14）

用 Instruments 的 os_signpost 工具查看 subsystem `com.transpeek.app`、category `pipeline` 的 `OCR` 和 `Translate` 区间。

- [ ] 约 1200×200 的区域，OCR 平均不超过 150ms（R14.1）
- [ ] 区域画面稳定到译文显示（不含网络）不超过 500ms（R14.3）
- [ ] 3 个区域、500 条历史时，内存不超过 200MB（R14.4）

## 设置与隐私

- [ ] 修改设置立即生效，无需重启（R13.2）
- [ ] 开机启动开关可用（R13.1）
- [ ] `~/Library/Application Support/TransPeek/` 下的文件中不包含 API Key（R8.2）
- [ ] 默认情况下 `log stream --predicate 'subsystem == "com.transpeek.app"'` 不输出识别文字；开启调试日志后才输出（R15.3）

- [ ] 菜单栏的权限警告打开“开始使用”；面板中“未配置翻译服务”的提示点击后打开“翻译服务”（S1.5）
- [ ] 识别页的采样预设与自定义切换正确；面板页的预览随字号、不透明度、显示原文实时变化（S4、S5）

## 识别结果整理（ocr-cleanup）

- [ ] Discord 聊天区域（Google 翻译）：名字和时间行显示为灰色小字、不翻译；“(已编辑)”被去掉；头像图标产生的乱码不出现（C1）
- [ ] 同一区域换成 LLM 翻译配置：回复引用、界面文字被移除，名字行显示为灰色小字，消息照常翻译；请求次数不增加（C2）
- [ ] 区域管理中关闭“过滤界面噪声”和“智能整理”后恢复为原来的行为（C1.1、C2.1）
- [ ] 不在底部时被移除的界面文字不计入“↓ N 条新消息”（C3.2）

## 合并面板（panel-groups）

- [ ] 升级前已有的区域：每个区域仍是一个独立面板，位置、透明度、字号与升级前一致（G6）
- [ ] 框选第二个区域，“显示在”默认“当前面板”：两个区域显示在同一个面板中，聊天在上、对话在下，默认比例约 3:2（G4.1、G2.3）
- [ ] “显示在”选择“新面板”时单独成面板，使用设置中的默认位置（G4.2）
- [ ] 只有一栏的面板与原来相同；多栏时顶部是细拖动条，每栏有小标题（G1.5）
- [ ] 游戏在前台时拖动栏之间的分隔条可以调整比例，光标变化；拖到最小值不再缩小；关闭并重新选择窗口后比例保留（G2.1、G2.2、G2.4）
- [ ] 栏的高度小于 80pt 时只显示最新一条（G2.5）
- [ ] 折叠一栏：只剩小标题，其他栏占满空间；折叠期间继续翻译，小标题显示新消息数；展开后恢复原比例（G3.2、G3.3）
- [ ] 只剩一栏展开时，该栏的折叠按钮不可用（G3.5）
- [ ] 面板贴在顶部或底部时，栏左右排列；折叠的栏是一条竖条（G1.2）
- [ ] 每栏的字号、显示原文互不影响；透明度、位置对整个面板生效（G1.3、G1.4）
- [ ] 栏菜单：上移、下移、移到新面板、移到其他面板；面板菜单：合并到其他面板（G4.3、G4.4）
- [ ] 区域管理中“面板”显示所在面板，修改后保存生效（G4.6）
- [ ] 关闭一栏只暂停该区域；关闭顶部拖动条的 × 暂停面板中所有区域；暂停全部后面板隐藏，恢复后栏回到原位置（G1.6、G1.7）
- [ ] 两个面板都贴在右侧时上下平分窗口高度，不重叠（G5）
